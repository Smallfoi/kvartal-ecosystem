# МАТА Лига — правила работы (Claude)

**Это НЕ «Квартал».** Это отдельное приложение, созданное копией «Квартала» 29.08.2026
под перестройку геймификации в «свою лигу» (решение владельца, `docs/DECISIONS.md` D-59).

## Чем «Лига» отличается от «Квартала»

| | «Квартал» (`mata_kvartal/`) | «Лига» (`mata_liga/`) |
|---|---|---|
| Назначение | стабильное приложение у тестировщиков | площадка для новой геймификации |
| Что туда идёт | исправления, устранение багов, мелкие улучшения | «своя лига»: зачёты, тропы, режимы, импорт с часов |
| Идентификатор | `ru.mata.kvartal` | `ru.mata.liga` |
| Имя пакета Dart | `kvartal_app` | `liga_app` |
| Имя на телефоне | КВАРТАЛ | ЛИГА |
| Канал обновлений | `app/kvartal/version.json` | `app/liga/version.json` |

Оба приложения ставятся на один телефон **одновременно** — разные идентификаторы, разные
песочницы данных. Это и есть смысл разделения: тестировщик не теряет рабочее приложение,
пока мы перестраиваем игру.

## Главное правило

**Правки в одном приложении не переносятся в другое сами.** Исправил баг в «Квартале» —
подумай, нужен ли он в «Лиге», и перенеси осознанно (и наоборот). Пока код почти одинаковый,
это дёшево; чем дальше «Лига» уходит вперёд, тем аккуратнее.

Общий backend один и тот же (`backend/django_api`), контракты API общие — их ломать нельзя
ни из «Лиги», ни из «Квартала»: на них живут ещё Store и сайт.

## Что строим

План работ: `docs/LEAGUE_PLAN.md`. Стратегия (зачем): `docs/STRATEGY_KVARTAL.md`.
Часы и партнёрские заявки: `docs/WEARABLES_PARTNERS.md`.

Кратко: одна пробежка попадает сразу в несколько зачётов (абсолютный, личный рекорд,
постоянство, своя лига по возрасту и полу, усилие по пульсу, клубный), бегун выбирает,
какие ему важны. Территории остаются, но становятся одним из режимов.

## Правила работы (те же, что и во всём монорепо)

- перед работой — `git checkout main && git pull`, прочитать свежее в `docs/WORKLOG.md`
  и весь `docs/PITFALLS.md`;
- `main` защищён: только ветка → PR → зелёный CI → squash;
- CI проверяет «Лигу» отдельной job `Flutter · liga-app` (analyze + test);
- дизайн/бренд/цвета/шрифты не трогаем без отдельной команды владельца;
- после работы — запись в `docs/WORKLOG.md`, решения в `docs/DECISIONS.md`,
  грабли в `docs/PITFALLS.md`.

## Технически

Flutter + Riverpod + go_router, как в «Квартале». Структура `lib/` не менялась:
`core/` (роутер, сервисы, тема), `features/` (экраны по областям), `shared/` (общие виджеты).

Сборка и проверка:

```
cd mata_liga
flutter pub get
flutter analyze
flutter test
```
