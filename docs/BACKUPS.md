# Бэкапы БД экосистемы МАТА

Логические дампы PostgreSQL/PostGIS + проверенное восстановление (launch §13). Инструмент —
`scripts/backup_db.py` (кросс-платформенный, работает через `docker compose exec`).

> **ПДн.** Дампы содержат персональные данные (телефоны, email, GPS-след, заказы). Каталог
> `backups/` и `*.sql.gz` — в `.gitignore`, **НИКОГДА не коммитить**. В проде дампы шифровать
> и хранить в приватном бакете Object Storage (D-31) с ограниченным доступом.

## Команды (из корня репо, Docker поднят)

```bash
python scripts/backup_db.py backup          # создать дамп → backups/staw_<ts>.sql.gz
python scripts/backup_db.py verify          # дамп + пробное восстановление + сверка (§13)
python scripts/backup_db.py restore <файл>              # восстановить в основную БД (ПЕРЕЗАПИСЬ)
python scripts/backup_db.py restore <файл> --db scratch # восстановить в другую БД
```

- **backup** — `pg_dump --clean --if-exists --no-owner` → gzip. Без временных файлов в контейнере.
- **verify** — доказывает, что дамп РЕАЛЬНО восстановим: разворачивает его в отдельную
  scratch-БД `kvartal_verify`, сверяет число таблиц и строк `accounts` с основной, затем
  удаляет scratch. **dev-данные не трогаются.** Именно это закрывает «проверено восстановление».
- **restore** — разворачивает дамп в указанную БД (по умолчанию основную — перезапись!).

## Прод (что осталось владельцу)

Инструмент готов; в проде нужно:
1. **Расписание** — `backup` по cron (или Celery-beat, D-07) ежедневно; хранить N последних + еженедельные.
2. **Выгрузка вне сервера** — дамп в Object Storage (Yandex, D-31), отдельный приватный бакет, шифрование.
3. **Снапшоты диска** — дополнительно к логическим дампам (быстрое восстановление всей VM).
4. **Регулярный `verify`** — периодически прогонять восстановление (бэкап без проверенного restore = иллюзия).
5. **Ретеншн/удаление** — сроки хранения дампов согласовать с политикой ПДн (§2 LAUNCH_READINESS).

## Проверено (dev)

`verify` на dev-БД: дамп создаётся, разворачивается в scratch, число таблиц и `accounts`
совпадает с основной → восстановление рабочее. См. запись в `docs/WORKLOG.md`.
