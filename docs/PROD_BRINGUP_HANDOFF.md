## Почему не довели до «живого» автоматически

Не было **рабочего канала доступа** к Yandex Cloud:
- личный OAuth-токен Яндекс блокирует для IAM-обмена (политика «issued after 2026-06-01»);
- **SSH:22 режет интернет-провайдер** (TCP проходит, sshd не отдаёт баннер; при этом GitHub:22
  с той же машины отвечает — значит режется путь к YC, а не машина);
- ключ сервисного аккаунта создан не был (был прислан KMS-ключ — это шифрование данных, не auth).

Грант доступа может выдать только владелец. Поэтому подготовлено «в одно действие».

## Как довести до боевого (выбери путь)

### Путь A — без SSH и без CLI (рекомендуется, обходит блок порта 22)
1. Пересоздать ВМ (или создать новую) с теми же параметрами (Ubuntu 24.04, 2/4, 30 ГБ SSD,
   логин `yc-user`, наш SSH-ключ, группа `mata-sg`).
2. В блок **«Метаданные» → user-data** вставить целиком файл
   **`brand/_prod/cloud-init-mata.yaml`** (там уже секреты и засев каталога).
3. Дождаться ~3–5 мин: сервер сам поставит Docker, склонирует репозиторий, поднимет
   db+redis+web+worker+beat. Проверить лог: файл `/var/log/mata-deploy.log` на ВМ.

### Путь B — дать доступ мне
Создать **авторизованный ключ сервисного аккаунта**: Консоль → **IAM → Сервисные аккаунты →
`mata-cli`** (роль `editor` на каталог) → **Создать авторизованный ключ** → скачать **JSON** →
положить в `Downloads`. Дальше я через `yc` (по HTTPS, порт 22 не нужен) всё доразверну и настрою.

## Обязательные шаги владельца после подъёма стека

1. **DNS в Beget** (панель домена `mata-club.ru` → DNS):
   - `api.mata-club.ru` → **A** → `<публичный IP ВМ>` (сделать IP **статическим** в VPC → IP-адреса).
   - `mata-club.ru` и `www` → на хостинг сайта (когда выложим витрину).
2. **TLS** (после того как DNS начал резолвиться на IP): на ВМ
   `cd /opt/mata/backend && make tls-issue`. Поднимет HTTPS (Let's Encrypt).
   Автообновление — cron (см. `docs/YANDEX_CLOUD.md` шаг 6/7).
3. **Проверка:** `curl https://api.mata-club.ru/v1/health` → `{"status":"ok"}`.
4. **2FA админки:** `docker compose -f docker-compose.prod.yml exec web python manage.py admin_2fa admin`
   (сохранить запасные коды отдельно).
5. **Ротировать секреты** из cloud-init (они были в метаданных ВМ): сменить
   `DJANGO_SECRET_KEY/JWT_SECRET/POSTGRES_PASSWORD` в `.env` и перезапустить стек.
