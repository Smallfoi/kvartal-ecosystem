# Юридические документы экосистемы МАТА (черновики)

Комплект документов, необходимых для работы экосистемы МАТА (Квартал + Store + Сайт) —
пользовательские соглашения, согласия, политика ПДн, оферта, правила баллов и сообщества.

> ## ⚠️ ЭТО ЧЕРНОВИКИ — НЕ ГОТОВЫЕ ЮРИДИЧЕСКИЕ ДОКУМЕНТЫ
> Подготовлены как **шаблоны, заточенные под реальную работу МАТА** (какие данные собираем,
> как работают баллы и т.д.), чтобы дать юристу точную отправную точку и сэкономить время.
> **Перед публикацией ОБЯЗАТЕЛЬНА проверка профильным юристом РФ** по 152-ФЗ (персональные
> данные), законам о защите прав потребителей, рекламе и электронной коммерции. Автор черновиков
> не является юристом; юридической силы эти тексты без проверки и утверждения оператором не имеют.

## Что заполнить перед использованием (реквизиты оператора)

Во всех документах есть плейсхолдеры в квадратных скобках — заполнить единожды:

- `[ОПЕРАТОР]` — юр. лицо/ИП (наименование). Напр.: ИП Иванов И.И.
- `[ОГРН/ОГРНИП]`, `[ИНН]` — регистрационные данные.
- `[ЮР.АДРЕС]` — юридический адрес.
- `[EMAIL]` — контактный e-mail для обращений/запросов ПДн (напр. privacy@mata-store.ru).
- `[САЙТ]` — домен сайта (напр. mata-store.ru).
- `[ДАТА]`, `[ВЕРСИЯ]` — дата и версия редакции документа.
- `[ВОЗРАСТ]` — возрастной порог (рекомендуется 18+ до отдельной детской модели, см. LAUNCH_READINESS §8).

## Как это связано с системой

Бэкенд уже умеет версионировать и выдавать эти документы (модуль `legal`):
- Модель `LegalDocument` (тип, версия, заголовок, текст, `is_required`, `published_at`).
- `GET /v1/legal/documents` — отдаёт опубликованные версии; аппы/сайт показывают их при регистрации.
- `POST /v1/legal/consent` — фиксирует, кто/когда/какую версию принял (аудит согласий, 152-ФЗ).

**Порядок ввода в работу:**
1. Юрист проверяет и правит эти черновики, заполняются реквизиты `[ОПЕРАТОР]`.
2. Загрузить как черновики: `python manage.py seed_legal_drafts` (создаёт записи `LegalDocument`, НЕ опубликованные).
3. В админке проверить и **опубликовать** нужные версии (проставить `published_at`).
4. Апп/сайт при регистрации требуют принять обязательные (`is_required`) — согласие фиксируется.
5. При существенном изменении — новая версия (новый `published_at`) → повторный запрос согласия.

## Что документы должны отражать (специфика МАТА — для юриста)

- **Единый аккаунт** по телефону (SSO), общий на Квартал/Store/Сайт; общий баланс баллов.
- **Данные:** телефон, e-mail, имя, город, адрес доставки, аватар; баллы и транзакции; заказы;
  сводки забегов и **геоданные территорий** (сырой GPS хранится на устройстве, на сервер идут сводки);
  клубы; токены устройств (пуши); согласия; события продуктовой аналитики.
- **Баллы** зарабатываются за бег/захваты в Квартале, тратятся в Store; баллы — НЕ деньги.
- **Приватность by design:** маршруты/позиция скрыты по умолчанию, публичность — явным действием.
- **Права субъекта ПДн реализованы в коде:** выгрузка (`GET /account/export`), исправление
  (`PATCH /profile`), удаление (`POST /account/delete`); сроки хранения/авто-удаление (retention).
