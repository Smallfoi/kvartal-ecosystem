# TestFlight — как раздать приложения владельцам айфонов

Пошаговая инструкция для владельца. Всё, что можно было сделать без Apple-аккаунта,
уже сделано: iOS-проекты собираются, права и фоновый режим прописаны, пайплайн заливки
готов (`.github/workflows/ios-testflight.yml`). Осталось то, что может сделать только
владелец — оформить аккаунт и передать ключ.

---

## Почему нельзя проще

На iPhone приложение **нельзя раздать файлом** — ни ссылкой, ни QR-кодом, ни по кабелю
с компьютера. Apple разрешает ставить приложения только из App Store, TestFlight или по
Ad Hoc-профилю. Все три пути требуют **Apple Developer Program**.

Отдельно про «бесплатные» способы (Sideloadly, AltStore): технически работают, но требуют
ввести **логин и пароль Apple ID** в стороннюю программу — это ключи от iCloud, почты и
платежей человека — и приложение перестаёт открываться через **7 дней**. Для друга это не
подарок, а обязанность ходить к компьютеру каждую неделю. Не рекомендуется.

---

## Шаг 1. Аккаунт Apple Developer — $99 в год

1. <https://developer.apple.com/programs/enroll/> — вход по Apple ID (лучше завести
   отдельный «рабочий» Apple ID, не личный).
2. Тип аккаунта:
   - **Individual (физлицо)** — быстрее, обычно 1–2 дня. В App Store издателем будет
     указано ваше имя.
   - **Organization (юрлицо)** — издателем будет «МАТА», но нужен номер **D-U-N-S**
     (бесплатно, получается 5–14 дней) и проверка юрлица. Дольше.

   Для тест-группы годится Individual; сменить на организацию можно позже, но приложения
   при этом переносятся отдельной процедурой.

3. **Оплата.** Российские карты обычно не проходят — это уже проверено на нашем проекте
   и записано в граблях. Нужна зарубежная карта. Подписка продлевается ежегодно; если не
   продлить — приложения из TestFlight пропадают.

## Шаг 2. Завести приложения в App Store Connect

<https://appstoreconnect.apple.com> → **My Apps** → «+» → New App. Для каждого приложения:

| Поле | Квартал | Store |
|---|---|---|
| Platform | iOS | iOS |
| Name | КВАРТАЛ | МАТА Store |
| Primary Language | Русский | Русский |
| Bundle ID | `ru.mata.kvartal` | `ru.mata.store` |
| SKU | `kvartal` | `mata-store` |

Bundle ID нужно сначала зарегистрировать: **Certificates, Identifiers & Profiles →
Identifiers → «+» → App IDs → App**. Для Квартала там же отметить возможность
**Background Modes** (фоновая геолокация) — остальное по умолчанию.

## Шаг 3. Создать ключ App Store Connect API

Это то, что заменяет пароли и позволяет мне заливать сборки автоматически.

1. App Store Connect → **Users and Access** → вкладка **Integrations** → **App Store Connect API**.
2. **«+»**, имя ключа — например `CI MATA`, роль — **App Manager**.
3. Скачать файл `AuthKey_XXXXXXXX.p8` — **скачивается только один раз**, сохранить надёжно.
4. Записать оттуда же: **Key ID** (8 символов) и **Issuer ID** (длинный, вида
   `69a6de7c-...`).
5. **Team ID** (10 символов) — <https://developer.apple.com/account> → Membership.

## Шаг 4. Передать это мне

Четыре значения кладутся в секреты репозитория
(Settings → Secrets and variables → Actions → New repository secret):

| Имя секрета | Что вставить |
|---|---|
| `APPSTORE_ISSUER_ID` | Issuer ID |
| `APPSTORE_KEY_ID` | Key ID |
| `APPSTORE_PRIVATE_KEY` | содержимое файла `.p8` целиком, вместе со строками `-----BEGIN PRIVATE KEY-----` и `-----END PRIVATE KEY-----` |
| `APPLE_TEAM_ID` | Team ID |

Секреты в GitHub только для записи: их не видно даже владельцу репозитория после
сохранения, и в логи сборки они не попадают. **Сам файл `.p8` в репозиторий не кладём
никогда** — репозиторий публичный.

Если удобнее — пришлите мне значения, и я заведу секреты сам.

## Шаг 5. Первая заливка (делаю я)

Actions → **iOS TestFlight** → Run workflow → выбрать приложение → запустить.
Пайплайн соберёт, подпишет (сертификат и профиль Xcode создаст сам по ключу API),
экспортирует `.ipa` и зальёт в App Store Connect.

Дальше на стороне Apple: обработка сборки **5–30 минут**, после чего она появляется
в TestFlight.

## Шаг 6. Добавить тестеров

В App Store Connect → приложение → **TestFlight**:

- **Внутренние тестеры** (до 100 человек) — те, кого вы добавите в Users and Access.
  Доступ сразу после обработки, **без проверки Apple**.
- **Внешние тестеры** (до 10 000 человек) — приглашаются по ссылке или по почте,
  но первая сборка для них проходит **Beta App Review** (обычно 1–2 дня).

Для друга проще всего: создать группу, включить **публичную ссылку** и отправить её.
Он ставит из App Store приложение **TestFlight**, открывает ссылку — и получает «Квартал».

Обновления после этого прилетают ему автоматически при каждой новой заливке.

## Что уже готово с нашей стороны

- iOS-проекты обоих приложений собираются на macOS-раннере (`ios-build.yml`, без подписи) —
  ошибки iOS-специфики ловятся бесплатно, до трат на Apple.
- Bundle ID: `ru.mata.kvartal` и `ru.mata.store`; название на экране — «КВАРТАЛ».
- Тексты разрешений на геолокацию, иконки всех размеров (1024 без альфа-канала, как
  требует Apple), минимальная версия iOS 13.
- **Фоновый режим геолокации** (`UIBackgroundModes: location`) — без него iOS усыпляет
  приложение при погашенном экране и трекинг пробежки обрывается.
- **Ответ про экспорт шифрования** (`ITSAppUsesNonExemptEncryption: false`) — иначе каждая
  сборка висит в TestFlight как «Missing Compliance» и тестеры её не видят.
- Пайплайн заливки `ios-testflight.yml`: номер сборки = число коммитов (та же нумерация,
  что у Android), `.ipa` сохраняется в артефактах на случай сбоя на стороне Apple.

## Сроки, если начать сегодня

| Этап | Сколько |
|---|---|
| Регистрация и оплата Apple Developer (Individual) | 1–2 дня |
| Завести приложения и ключ API | 30 минут |
| Первая заливка и обработка Apple | ~1 час |
| Beta App Review (только для внешних тестеров) | 1–2 дня |

То есть друг получит приложение **через 2–4 дня** после оплаты аккаунта, а если добавить
его внутренним тестером — в тот же день, когда пройдёт первая заливка.
