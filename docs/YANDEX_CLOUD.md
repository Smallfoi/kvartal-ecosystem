# Подключение прод-инфраструктуры МАТА — по порядку

Пошаговый порядок «от нуля до работающего прода»: что покупаем, что настраиваем, чем
проверяем каждый шаг. Конкретизирует D-28 (бюджетная конфигурация) и D-17 (выбор облака);
операторские команды — `docs/DEPLOY.md`, готовность к запуску — `docs/LAUNCH_READINESS.md`.

> **Разделение труда.** Аккаунты, оплата, домен, юрлицо — только владелец (нужны паспорт,
> карта, телефон, подтверждение личности). Конфиги, скрипты и проверки — уже в репозитории,
> их писать не нужно. В каждом шаге отмечено, чья зона.

## Шаг 0. До первой траты

- **ИП на УСН** (D-18) — нужен для платёжного аккаунта с закрывающими документами, для
  ЮKassa (юрлицо обязательно) и как оператор ПДн. ✅ **Зарегистрирован** (2026-08-13).
- **ОКВЭД в ЕГРИП** — добавить коды под интернет-торговлю, ПО и спорт (заявление Р24001,
  0 ₽, ~5 рабочих дней). Без них возможен отказ на модерации ЮKassa и блокировка поступлений
  банком. Список кодов и порядок — `docs/STEP2_OPERATOR_AGE.md` §4a. ⏳ **В работе.**
- **Домен** `staw.ru` у регистратора (Beget/RU-CENTER, по D-17 DNS может остаться там).
  Проверить занятость до всего остального — от домена зависят все конфиги.

## Шаг 1. Yandex Cloud: аккаунт и платёжный аккаунт

1. `console.yandex.cloud` → вход по Яндекс ID.
2. Создать **облако** `staw` и внутри **каталог** `staw-prod` (второй каталог `staw-staging` — позже).
3. Платёжный аккаунт: тип **ИП/юрлицо** (ИНН + расчётный счёт) — иначе не будет актов и НДС-документов.
4. Активировать **грант/пробный период** (по D-28: до 4 000 ₽ физлицам, до 10 000 ₽ юрлицам).
5. **Регион только `ru-central1`** — данные россиян должны храниться в РФ (242-ФЗ, §2 LAUNCH_READINESS).
   Зона доступности — `ru-central1-a` (VM и диски должны быть в одной зоне).

**Проверка:** в консоли видны каталог `staw-prod` и баланс с грантом.

## Шаг 2. Домен и DNS

| Запись | Тип | Значение | Когда |
|---|---|---|---|
| `api.staw.ru` | A | публичный IP машины | после шага 3 |
| `staw.ru`, `www` | A / CNAME | хостинг сайта | при выкладке сайта |
| `cdn.staw.ru` | CNAME | `staw-media.website.yandexcloud.net` | опционально, шаг 4 |

**Проверка:** `nslookup api.staw.ru` возвращает IP машины. DNS расходится до часа — делать
до выпуска сертификата, иначе Let's Encrypt не подтвердит владение доменом.

## Шаг 3. Виртуальная машина

Compute Cloud → **Создать ВМ**:

| Параметр | Значение | Почему |
|---|---|---|
| Образ | Ubuntu 24.04 LTS | свежий curl (нужен `--aws-sigv4` для выгрузки бэкапов) |
| Платформа | Intel Ice Lake | текущее поколение |
| vCPU | 2, доля **50%** | Django на старте не упирается в CPU; поднять — 2 клика |
| RAM | 4 ГБ (8 ГБ, если сразу GlitchTip) | RAM — самая дорогая часть счёта |
| Диск | network-SSD, 30 ГБ | БД любит SSD; диск потом **только увеличивается** |
| Публичный IP | **статический** | иначе IP слетит при перезапуске и сломает DNS |
| Прерываемая | **НЕТ** | прерываемая гасится в любой момент — только для dev |
| Доступ | SSH-ключ, логин `yc-user` | пароли не использовать |

Группа безопасности: входящие **22** (только со своего IP), **80**, **443**. Больше ничего —
Postgres и Redis наружу не публикуются (в `docker-compose.prod.yml` у них нет проброса портов).

После создания:

```bash
ssh yc-user@<IP>
sudo apt update && sudo apt install -y docker.io docker-compose-v2 git make
sudo usermod -aG docker $USER && exit   # перезайти, чтобы группа применилась
```

**Проверка:** `docker run --rm hello-world` отрабатывает без sudo.

## Шаг 4. Object Storage: два бакета и ключи

| Бакет | Доступ | Зачем | Жизненный цикл |
|---|---|---|---|
| `staw-media` | публичный на чтение | фото товаров, аватары, баннеры (D-31) | — |
| `staw-backups` | **приватный** | дампы БД (`pg_dump`) | удалять объекты старше 30 дней |

Сервисный аккаунт: IAM → **Сервисные аккаунты** → `staw-app`, роль `storage.editor` на каталог →
**Создать статический ключ доступа**. Идентификатор (`YCAJE…`) → `MEDIA_S3_ACCESS_KEY`,
секрет (`YCP…`) → `MEDIA_S3_SECRET_KEY`. **Секрет показывается один раз.**

**Проверка:** после шага 5 загрузить аватар в приложении — файл появится в бакете, а URL
картинки будет вести на `storage.yandexcloud.net` (или на `cdn.staw.ru`).

## Шаг 5. Деплой бэкенда

```bash
git clone https://github.com/Smallfoi/mata-ecosystem.git && cd mata-ecosystem/backend
cp .env.prod.example .env && nano .env
python3 -c "import secrets; print(secrets.token_urlsafe(64))"   # ×2 — для двух разных секретов
cp nginx/staw.conf.example nginx/staw.conf && nano nginx/staw.conf   # подставить домен
make prod-deploy
```

Что обязательно заполнить в `.env`:

| Переменная | Значение |
|---|---|
| `DJANGO_SECRET_KEY`, `JWT_SECRET` | два **разных** случайных секрета |
| `DJANGO_ALLOWED_HOSTS` | `api.staw.ru` |
| `DJANGO_CORS_ORIGINS` | `https://staw.ru,https://www.staw.ru` |
| `POSTGRES_PASSWORD` | сильный пароль |
| `REDIS_URL` | `redis://redis:6379/0` |
| `MEDIA_S3_BUCKET/ACCESS_KEY/SECRET_KEY` | из шага 4 |
| `BACKUP_S3_BUCKET` | `staw-backups` |
| `TLS_DOMAIN`, `TLS_EMAIL` | для шага 6 |

Стек поднимает: Django+gunicorn, PostGIS, Redis, **Celery worker + beat**, nginx.
При `DJANGO_DEBUG=0` приложение не стартует с дефолтными секретами (fail-fast, `common/prodcheck.py`).

**Проверка:** `make smoke` → `✅ Smoke OK` (health + каталог + баннеры + оба Celery-сервиса).
Затем `docker compose -f docker-compose.prod.yml --env-file .env exec -T web python manage.py check_launch_readiness`
и `python manage.py seed_catalog` — засеять каталог. **Сразу сменить логин/пароль админки** и
ограничить `/admin/` по IP.

## Шаг 6. TLS-сертификат (бесплатно)

```bash
make tls-issue     # первый выпуск, nginx встанет на ~минуту
```

Автообновление — в cron (Let's Encrypt живёт 90 дней, обновляется без простоя):

```cron
0 3 * * 1  cd /home/yc-user/mata-ecosystem/backend && ./deploy/tls.sh renew >> logs/tls.log 2>&1
```

**Проверка:** `curl -I https://api.staw.ru/v1/health` → `200`, `http://` редиректит на `https://`.

## Шаг 7. Бэкапы и мониторинг

```cron
0 4 * * *  cd /home/yc-user/mata-ecosystem/backend && ./deploy/backup.sh >> backups/cron.log 2>&1
```

`backup.sh` делает дамп, проверяет что он непустой, **выгружает в `staw-backups`** и чистит
локальные копии старше 14 дней. Плюс снапшоты диска по расписанию в консоли облака.

Внешний мониторинг: UptimeRobot на `https://api.staw.ru/v1/health` каждые 5 минут → алерт
в Telegram/почту. Пинговать нужно **снаружи**: сервер не сообщит, что он упал.

**Проверка (обязательно, до запуска):** восстановить свежий дамп на staging —
`make restore FILE=backups/staw_<дата>.sql.gz`. Бэкап без проверенного восстановления не считается бэкапом.

## Шаг 8. SMS-вход (smsc.ru)

Регистрация → договор → пополнить баланс → **согласовать имя отправителя** (без него SMS не уходят,
согласование занимает дни — начинать заранее). В `.env`: `SMS_PROVIDER=smsc`, `SMS_LOGIN`, `SMS_PASSWORD`,
затем `make prod-up`. Без этих переменных вход работает в dev-режиме с кодом `1234` — **в проде это дыра**.

**Проверка:** вход по своему реальному номеру присылает настоящую SMS с кодом.

## Шаг 9. Оплата (ЮKassa)

Регистрация магазина на ИП → модерация → `YOOKASSA_SHOP_ID` + `YOOKASSA_SECRET_KEY` →
в `.env` плюс `PAYMENT_PROVIDER=yookassa`. Без них заказ считается оплаченным сразу (dev-режим).

**Проверка:** тестовый заказ на 1 ₽ проходит и виден в личном кабинете ЮKassa.

## Шаг 10. Пуши (RuStore Push)

Консоль RuStore → проект → ключ push-сервиса → `PUSH_PROVIDER=rustore`, `RUSTORE_PUSH_KEY`.
Без ключа лента уведомлений в приложении работает, наружу пуши не уходят (D-25).

## Шаг 11. GlitchTip — «видимость ошибок» (D-32)

Ставится на ту же машину отдельным compose (нужно ~1 ГБ RAM — отсюда вариант 8 ГБ в шаге 3).
Даёт DSN → в `.env` бэкенда `SENTRY_DSN` + `SENTRY_ENVIRONMENT=production`, дальше — SDK в
приложениях. План внедрения — `docs/OBSERVABILITY.md`.

## Шаг 12. Приложения и сайт на прод-домен

```bash
flutter build apk --release --target-platform android-arm64 \
  --dart-define=SPORT_STORE_API_BASE_URL=https://api.staw.ru/v1
flutter build apk --release --target-platform android-arm64 \
  --dart-define=KVARTAL_API_BASE_URL=https://api.staw.ru/v1
```

Сайт: в `САЙТ МАТА/ecosystem.js` заменить `PROD_API` на реальный домен.

**Проверка:** войти одним номером в оба приложения и на сайт — баланс баллов везде одинаковый.

## Бюджет

**Ежемесячно:** Yandex Cloud 1 700–2 500 ₽ · SMS 200–1 000 ₽ · домен ~150 ₽ · банк 0–1 500 ₽ →
**≈ 2 000–5 000 ₽/мес**. ЮKassa — без абонплаты, ~3% с транзакции.

**Разово:** домен 1 000–3 000 ₽ · юрист (политика ПДн, согласия, оферта) 5 000–60 000 ₽ ·
Google Play 2 300 ₽ · первое пополнение smsc 500–1 000 ₽ → **≈ 9 000–70 000 ₽**.

**Первый год:** ≈ 62 000 ₽ без взносов ИП, ≈ 119 000 ₽ с ними (~57 000 ₽/год, платятся
независимо от выручки). Первые ~2 месяца облака закрывает грант.

Тарифы (проверено 2026-08-13): vCPU 100% — 0,7017 ₽/ч · RAM — 0,2441 ₽/ГБ/ч · публичный IP —
0,1524 ₽/ч · Object Storage — 1,01–1,43 ₽/ГБ/мес · первые 100 ГБ исходящего трафика в месяц бесплатно.

## Что НЕ покупаем на старте

Managed PostgreSQL (от ~5 500 ₽/мес), Managed Redis, Kubernetes, балансировщик, CDN,
Certificate Manager. Всё это включается по триггеру роста, а не «на всякий случай».
Прерываемые VM — только под dev/staging, никогда под прод.
