# PITFALLS — грабли и тупиковые попытки (НЕ повторять)

То, что уже сломалось или не сработало, и как с этим жить. **Перед работой прочитать
целиком.** Нашёл новое — допиши сюда, чтобы второй агент не наступил на те же грабли.

## FadeForwardsPageTransitionsBuilder ломает подмену экрана в ShellRoute
Добавленный в тему (D-42) `pageTransitionsTheme` с `FadeForwardsPageTransitionsBuilder`
для Android приводил к тому, что при переключении вкладок внутри `ShellRoute` новый экран
**монтировался, но не рисовался**: запросы к API уходили, `initState` отрабатывал, а на
экране оставалась пустота — даже закреплённая (`pinned: true`) шапка не появлялась.
Ошибок в логах при этом НЕТ, поэтому ищется долго.
Симптом проявлялся не всегда: после «Профиля», особенно прокрученного, — стабильно.
Лечение: не задавать `pageTransitionsTheme` для Android (штатный `ZoomPageTransitions`
работает корректно). Если захочется своей анимации перехода — проверять именно
переключение вкладок в ShellRoute, а не только push/pop.

## Диагностика «экран пустой, ошибок нет»
Порядок, который сработал: (1) убедиться по логам бэкенда, что экран смонтировался и
сделал запрос; (2) проверить `adb logcat` на исключения Dart; (3) вставить временный
цветной прямоугольник первым элементом — если он виден лишь в уголках карточки, значит
элементы накладываются, а если не виден вовсе, значит не рисуется весь экран;
(4) отключать по одному недавние изменения темы. Пустой экран без исключений — почти
всегда анимация/трансформация, а не логика.

## Несимметричный знак нельзя центрировать по габаритной рамке
У знака МАТА один длинный луч вправо и два диагональных влево. Габаритную рамку растягивает
правый луч, поэтому её центр не совпадает с оптическим: замерено смещение **41.6 из 280
единиц (~15% ширины знака)**, на иконке 1024 px это **96 px** — владелец увидел глазом сразу.
Центрировать такие знаки по **центру масс** залитой площади (у этого знака он совпадает с
точкой схода лучей), а размер задавать **описанной окружностью**, а не шириной рамки: иначе
доля плитки, занятая знаком, скачет в зависимости от того, куда торчат лучи.
Проверять числом: центр масс лаймовых пикселей готового PNG против центра плитки
(после правки — 0.6 px из 1024).

## `convert` в git-bash на Windows — это НЕ ImageMagick
`command -v convert` находит `C:\Windows\System32\convert.exe` — системную утилиту
преобразования FAT→NTFS. Запуск её с аргументами ImageMagick в лучшем случае ничего не
сделает, в худшем — обратится к диску. Для растеризации использовать Python + PIL
(`tools/brand/make_app_icons.py`), он и так есть в окружении. ImageMagick/cairo на Windows
ставятся плохо, закладываться на них не стоит.

## Масштаб иконки Android нельзя брать тот же, что для iOS
У adaptive-иконки холст 108dp, но лаунчер показывает только центральные 72dp и режет маской
(круг/скруглённый квадрат — зависит от прошивки). Знак в 0.62 ширины, нормальный для iOS,
теряет лучи. Для adaptive-слоя — 0.41 холста, это те же ~62% внутри видимой зоны.
Проверять маской обоих видов, а не «на глаз» по PNG.

## iOS-иконки с прозрачностью App Store отклоняет
Любой файл в `AppIcon.appiconset` должен быть RGB без альфа-канала. PIL по умолчанию
сохранит RGBA, если исходник был с прозрачностью, — при сборке иконок явно приводить к RGB
и проверять `Image.open(p).mode == 'RGB'`.

## git-bash подменяет пути внутри `docker compose exec`

**Симптом:** `docker compose exec web python /tmp/loadtest.py` → `can't open file
'/app/C:/Users/.../Temp/loadtest.py'`. MSYS считает `/tmp/...` windows-путём и разворачивает его
ещё до передачи в контейнер.

**Как правильно:** завернуть команду в `sh -c` с одинарными кавычками —
`docker compose exec -T web sh -c 'python /tmp/loadtest.py --tokens /tmp/tokens.txt'`.
Либо префикс `MSYS_NO_PATHCONV=1`.

**Рядом:** в контейнере `web` нет `curl`, `ps` и `pkill` — проверять сервисы изнутри через
`python -c "import urllib.request; ..."`, а фоновый процесс гасить перезапуском контейнера
(`docker compose restart web`), а не поиском PID.

## Две агент-сессии в одном чекауте D:\MyProjectsCLAUDE — заметают правки друг друга

**Симптом:** ветка «сама» переключилась; коммит ушёл не в ту ветку; чужой коммит
содержит твои файлы (add -A захватил незакоммиченные правки соседа); файлы в рабочем
дереве «сами» меняются. Реальный случай 2026-08-14: сессия диаграмм (PR #328) захватила
правки login.html + plans/ сессии аудита анимаций.

**Как правильно:** в один момент времени в основном чекауте работает ОДНА сессия.
Параллельной работе — отдельный `git worktree add <путь> <ветка>` (пример уже есть:
wt-tools для feat/kvartal-tools-tab). Перед каждым commit проверять
`git branch --show-current`; в add перечислять файлы явно, не `git add -A`.

## Проверка доменов .RU: whois.com врёт, RDAP-хост не резолвится

**Симптом:** `whois.com/whois/<имя>.ru` показывает «This domain is already registered by
someone else» и предлагает выкуп через Sedo — для **свободного** домена. `rdap.tcinet.ru`
из рабочей среды не резолвится (`ENOTFOUND`).

**Как правильно:** TCP-запрос к авторитетному whois реестра .RU напрямую:
```python
import socket
s = socket.create_connection(("whois.tcinet.ru", 43), timeout=12)
s.sendall(b"example.ru
")
print(s.recv(65535).decode("utf-8", "replace"))
```
Свободный домен → `No entries found for the selected source(s).`
Занятый → строки `domain: / state: / registrar: / created: / paid-till:`.
Дополнительная сверка: `Resolve-DnsName -Type NS` — если делегирование есть, домен точно занят
(обратное неверно: занятый домен может быть без NS).

**Товарные знаки** машинно не проверяются: ФИПС, brand-search, linkmark — только
JS-формы или платный доступ. Не выдумывать результат — отдавать владельцу на проверку
патентному поверенному.

## Конструктор витрины / мини-CMS сайта (редактируемость)
- **Фото Бег/Тренировка/Город «не менялись» кликом (долго не мог найти).** Причина: служебная панель
  `.staw-tools` — это `<div>`, а на сайте есть `.cinema-card div{position:absolute;left/right/bottom;z-index:1}`
  (тег+класс = выше специфичность) → ловит наш служебный div и РАСТЯГИВАЕТ его на всю карточку. Панель
  прозрачна (`opacity:0`), но при hover получает `pointer-events:auto` и перехватывает клик по фото. **Решение:**
  CSS всех служебных оверлеев конструктора (`.staw-tools`, `.staw-bg-btn`) фиксировать через `!important`
  (position/top/right/left/bottom/width/height/margin/z-index), чтобы CSS сайта не мог их растянуть. Плюс:
  клик по декоративному `::after`-оверлею поверх фото даёт `e.target` = карточка (не `<img>`) — в обработчике
  нужен fallback «взять фото ближайшей карточки». И слать в конструктор `img.src` (абсолютный), не
  `getAttribute('src')` (относительный) — иначе превью на :8000 не грузит картинку с :5577.
- **UI-баги конструктора НЕЛЬЗЯ дебажить jsdom** — он не воспроизводит hit-тест, `:hover`, нативный drag
  картинок, кросс-фрейм postMessage-геометрию. Гнать реальный **Chromium** (`puppeteer-core` + системный
  `C:\Program Files\Google\Chrome\Application\chrome.exe`, `headless:"new"`) и физически кликать по координатам.
  Именно так нашлась растянутая панель (два «фикса вслепую» до этого не помогли).
- **Django кэширует шаблоны (DEBUG=False в контейнере).** После правки `templates/admin/merch_console.html`
  правка НЕ видна на живом `/admin/merch/`, пока не `cd backend && docker compose restart web`. А сайт на :5577
  отдаёт `no-store` → там editor.js/content.js/styles свежие сразу после `git pull`.
- **hero-кнопки (и любые CTA) не редактировались кликом** — их «съедал» `pointer-events:none`
  в `editor.js` (стоял, чтобы клик не навигировал). Он же блокировал клик-на-правку. **Решение:**
  снять `pointer-events:none` с редактируемых кнопок; навигацию гасит `preventDefault()+stopPropagation()`
  в capture-обработчике клика (он же не даёт сработать штатному обработчику фильтра/логина).
- **В `<img>` нельзя вложить кнопку «Скрыть»** (void-элемент — `appendChild` не рендерится). Для
  фото-блоков (референсы) кнопку скрытия НЕ создаём — им доступны reorder и замена фото. Пропускаем
  void-теги (`IMG/INPUT/BR/HR/…`) в `initHide()`.
- **Гонка «черновик ↔ опубликованное»:** `editor.js` слал `ready` сразу, родитель накладывал черновик,
  а `content.js` (async fetch) применял ОПУБЛИКОВАННОЕ ПОЗЖЕ и **затирал черновик**. Решение: `content.js`
  после применения базы шлёт событие `staw-content-applied`; `editor.js` шлёт `ready` только после него
  (или по таймауту-страховке) → родитель кладёт черновик последним.
- **Перепорядок/скрытие НЕ требуют новых эндпоинтов** — это просто ключи в `SiteContent`:
  `order.<group>` (JSON-массив `data-sid`) и `hidden.<key>` ("1"/""). Публикуются тем же `/site-content`.
  Значение "" = «нет» (⇒ `content.js` пропускает пустое ⇒ дефолт HTML). Контракты бэкенда не трогаются.
- **Клиентский JS сайта: СИНТАКСИС теперь в CI** (job `Site · JS` — `node --check` на все `САЙТ МАТА/*.js`;
  ловит рецидивные синтакс-ошибки, ломавшие витрину/конструктор). **Поведение (jsdom) — по-прежнему вручную:**
  прогон реальных файлов в jsdom (применение порядка/скрытия/текста/фото, edit vs live, хендшейк) CI НЕ покрывает —
  `node --check` проверяет только парсинг, не исполнение. Не полагаться только на «выглядит верно».

## Redis / Celery (D-07, фоновые задачи)
- **Новая Python-зависимость → пересобрать образ web/worker/beat.** Код монтируется томом
  (`./django_api:/app`), но пакеты ставятся при **build**. Добавил `celery` в `requirements.txt`, а
  `docker compose exec web ...` падал `service "web" is not running` / `ImportError`. Решение:
  `docker compose up -d --build` (пересобирает образ со свежими зависимостями). `pip install` внутрь
  живого контейнера — только для быстрой разовой проверки (теряется при recreate).
- **Тесты в dev-контейнере бьют по РЕАЛЬНОМУ брокеру.** В compose у web задан `REDIS_URL` ⇒
  `CELERY_TASK_ALWAYS_EAGER=False` ⇒ `create_notification` в тестах реально шлёт `send_push` в очередь
  (worker их выполняет, no-op=0 — на assert'ы не влияет). Чтобы тест был детерминированным и в dev, и в
  CI, форсируй eager: `@override_settings(CELERY_TASK_ALWAYS_EAGER=True, CELERY_TASK_EAGER_PROPAGATES=True)`.
- **CI не поднимает Redis** (сервис только `postgres`). Это ОК: без `REDIS_URL`/`CELERY_BROKER_URL` бэкенд
  сам уходит в EAGER (задачи inline). НЕ завязывай тесты на живой брокер/worker — только eager.
- **`crontab` для beat импортируется в settings** (`from celery.schedules import crontab`) — значит `celery`
  обязан быть в requirements, иначе `manage.py check` падает на импорте settings. Он там есть.

## Кэш агрегатов (D-29, лейдерборд / me-stats)
- **Тест «GET → мутация → GET того же ключа» отдаст УСТАРЕВШЕЕ**, если мутация не инвалидирует кэш.
  Лейдерборд кэшируется по TTL БЕЗ пер-write инвалидации — в тесте после прямой вставки данных дерни
  `cache.clear()` перед повторным GET (см. `test_leaderboard_served_from_cache`). `/me/stats` инвалидируется
  автоматически через `add_txn` — но прямое создание Run/Order (мимо add_txn) кэш НЕ сбросит (до safety-TTL).
- **`ApiTestCase.setUp` уже зовёт `cache.clear()`** перед каждым методом → между тестами протечек нет. Но
  `cache.clear()` на РЕАЛЬНОМ Redis (dev-стек) чистит ВЕСЬ кэш инстанса, включая живое приложение (OTP/лимиты/
  лейдерборд) — прогон тестов против живого стека сбрасывает dev-кэш. Для тестов это ок (отдельная тест-БД, кэш
  восстановится), но не удивляйся «сбросу» OTP/лимитов после локального `manage.py test`.
- **`isMe`/`me`/`isMine` НЕ клади в кэш** — это пер-юзерные поля. Кэшируй юзеро-НЕзависимую часть (ранжированный
  список), а персональные флаги навешивай на запрос из закэшированного. Иначе один юзер увидит isMe другого.

## Flutter сборка/установка на устройство (ВАЖНО — стоило доверия владельца)
- **Инкрементальная `flutter build apk` может отдать СТАРЫЙ скомпилированный код** части экранов после серии правок/мержей/`git pull` (mtime/кэш kernel). APK получается «винегретом»: одни экраны новые, другие старые. CI при этом зелёный (CI собирает с нуля). **Перед сборкой на телефон ВСЕГДА `flutter clean` + `flutter pub get` + build.** Это решает.
- **`adb install -r` НЕ перезапускает уже открытое приложение** — старый процесс крутится дальше, кажется «ничего не установилось». После установки: `adb shell am force-stop <pkg>` + перезапуск (а лучше — полное `adb uninstall`+install при сомнениях).
- **Скрин-проверка фиксов — ОБЯЗАТЕЛЬНО прокручивать экран до конца** (не только верх): убранный/добавленный блок может быть внизу. Скрин только верха ввёл и меня, и владельца в заблуждение.
- **`Row(crossAxisAlignment: stretch)` + `Expanded` внутри `ListView` без `IntrinsicHeight`** → строка получает неограниченную высоту, и виджеты НИЖЕ первой такой строки рендерятся ПУСТЫМИ (занимают место, но невидимы; в release — без ошибки в логах). Лечится обёрткой `IntrinsicHeight(child: Row(...))`. (Поймал на экране «Моя статистика» #202.)

## Прод-деплой (найдено на dry-run прод-стека)
- **`SECURE_SSL_REDIRECT=True` (DEBUG=0) форсит HTTP→HTTPS.** Прямой запрос к gunicorn (smoke-тест, healthcheck, отладка) БЕЗ заголовка `X-Forwarded-Proto: https` получает 301 на `https://…` и падает (`SSL: WRONG_VERSION_NUMBER`, т.к. gunicorn слушает plain HTTP). Через nginx всё ок (он шлёт этот заголовок). Решение: в прямых проверках слать `X-Forwarded-Proto: https` (так и сделано в `deploy/smoke.sh`) или ходить через nginx.
- **Dry-run прод-стека ОКУПАЕТСЯ:** `docker compose -p stawdry -f docker-compose.prod.yml --env-file .env up -d db redis web` (изолированный проект, без nginx, со своим `.env`) ловит проблемы прод-конфига до реального хостинга. Так и нашли пункт выше. **Обязательно свой `-p`/`COMPOSE_PROJECT_NAME`:** без него прод-compose берёт то же имя проекта, что и dev (оба лежат в `backend/`), и `down -v` снесёт dev-тома с тестовой БД.
- **`ALLOWED_HOSTS` в проде = только домен → прямой запрос на `127.0.0.1` получает 400 DisallowedHost.** `smoke.sh` ходил внутрь контейнера по `127.0.0.1:8000` и на исправно работающем проде вернул бы 400 → `make prod-deploy` падал бы на последнем шаге. Решение: в прямых проверках слать `Host:` = первый хост из `DJANGO_ALLOWED_HOSTS` (Django сверяет именно заголовок, порт игнорирует). Ослаблять `ALLOWED_HOSTS` ради теста — НЕ надо.
- **`grep -q '['` — это невалидная регулярка, а не подстрока.** Проверка «ответ похож на JSON-массив» падала с `Invalid regular expression` на любой платформе. Для сравнения с подстрокой всегда `grep -qF`.
- **Celery в проде не поднимался вообще:** `worker`/`beat` были только в dev-compose. Молча не выполнялись чистка данных с истёкшим сроком хранения (152-ФЗ), чистка территорий, парсер «Стартов». По API это не видно — теперь `smoke.sh` проверяет, что оба сервиса running.
- **Дамп БД рядом с БД — не бэкап.** `backup.sh` писал только на локальный диск: отказ диска убивает и базу, и все её бэкапы. Теперь дамп уходит в Object Storage (`BACKUP_S3_BUCKET`) подписью SigV4 через `curl --aws-sigv4` — без доп. пакетов, но нужен curl ≥ 7.75 (в Ubuntu 24.04 есть).

## Окружение / Windows
- **Кириллица в PowerShell бьётся** в `?????`/мусор при записи файлов и heredoc. Решение:
  UTF-8-тексты писать файловым инструментом (Write) или через Python с `encoding='utf-8'`. Не писать кириллицу через PowerShell here-string.
- **Кириллица в `curl --data '...'` (git-bash) тоже бьётся** — JSON с кириллицей в inline-аргументе/shell-переменной приходит мусором, PATCH затирает данные. (Затёр так адреса тест-юзера при API-round-trip.) Решение: тело писать в файл UTF-8 (Python/Write) и слать `curl --data-binary @file -H "Content-Type: application/json; charset=utf-8"`.
- **Перед `git add`/commit — проверять `git status`:** в рабочем дереве могут лежать ЧУЖИЕ незакоммиченные изменения (WIP параллельного чата) или застейдженные удаления. Раз так в коммит просочилось удаление `mata_store/IDEAS.md` (#182). Добавлять ТОЛЬКО свои файлы по явным путям и сверять `git status -s` до коммита.
- **PowerShell помечает stderr нативных команд как «ошибку»** (git/gh пишут прогресс в stderr). Это НЕ всегда падение — смотреть фактический результат, а не только «красный» вывод.
- **`/tmp` различается** для git-bash и Windows-python: файл, записанный bash в `/tmp`, Windows-python по `/tmp/...` не находит. Не передавать пути `/tmp` между ними; использовать абсолютные Windows-пути или один интерпретатор.
- **`curl -d '{...кириллица...}'` в git-bash бьёт UTF-8** — тело уходит мусором, запрос молча падает (юзер не создаётся, токен пустой). Для API-проверок с кириллицей использовать Django **test Client** (UTF-8 гарантирован) или `curl --data @файл`.
- **`docker compose exec ... /tmp/x.py` — MSYS конвертит `/tmp` в win-путь** (`C:/Users/.../Temp/x.py`) → «No such file». Ставить `MSYS_NO_PATHCONV=1` перед командой. И скрипт для Django класть в **`/app`** (а не `/tmp`): python добавляет в `sys.path` каталог скрипта, а `config` лежит в `/app` → иначе `ModuleNotFoundError: config`.
- **Docker: web перестаёт резолвить host `db`** (`failed to resolve host 'db'`) после нескольких `docker compose restart` — DNS в compose-сети отваливается, хотя сам db healthy. Лечится `docker compose up -d --force-recreate web` (просто restart не помогает). GitHub API/git тоже периодически моргают (EOF/SSL handshake) — повторять с ретраями.

## CI / branch protection
- **Переименование CI-джобы, которая в required status checks, блокирует мерж.** Имя job (`name:` в ci.yml) = контекст в ruleset `protect-main`. Если поменять имя (напр. `Backend · FastAPI`→`Backend · Django`), старый контекст в required больше не появится → PR висит «Expected». Решение: синхронно обновить контексты в ruleset через `gh api -X PUT repos/<owner>/<repo>/rulesets/<id> --input body.json` (тело с `rules[].required_status_checks` писать ФАЙЛОМ — там «·» не-ASCII, PowerShell бьёт). ID правила: `gh api .../rulesets`.

## Backend (Django + Docker, dev)
- **Docker Desktop в dev иногда сам останавливается** (`failed to connect to the docker API ... pipe`),
  и тогда бек на :8000 недоступен. Симптомы в приложении: `DioException`, `Connection closed before full
  header`, `Connection refused`, «нет товаров»/пустые экраны. ПЕРВЫМ делом проверить `GET /v1/health`;
  если бек лежит — запустить Docker Desktop и `cd backend && docker compose up -d`.
- **Не диагностировать «обрыв соединения»/«нет данных» как баг клиента, пока не проверил, что бек жив.**
  Не раз это был упавший Docker/бек, а не код приложения.
- Логи бэка: `cd backend && docker compose logs web` (свежие — `--since 30s`); `docker compose exec`
  запускать ТОЛЬКО из папки `backend/` (иначе `no configuration file provided: not found`).

## Телефон / устройство
- **Dev-бек доступен телефону только по USB** (`adb reverse tcp:8000 tcp:8000`) или по Wi-Fi (а там фаервол Windows).
  На улице связи НЕТ → начисления должны идти через офлайн-очередь, иначе теряются.
- **Тест «пробежка → баллы» требует реального движения по GPS.** Стоящий телефон = 0 км = 0 баллов
  (пробежка с `route.length<=1` даже не сохраняется). Мок-локаций на физическом устройстве нет из коробки.
- Кнопка СОХРАНИТЬ/нижняя навигация близко — при тапах через `adb input` легко промахнуться (мерить по координатам).
- Очистка текстового поля через `adb`: `KEYCODE_MOVE_END` не работает на этой клавиатуре; чистить `tap + N×KEYCODE_DEL(67) + N×KEYCODE_FORWARD_DEL(112)`.
- Скриншоты: устройство 1224×2720; ресайз до 600 шириной (scale ≈2.04). Чёрный кадр = погас экран (`input keyevent KEYCODE_WAKEUP`).

## Flutter ↔ backend (профиль / аватар)
- **Загрузка аватара через пакет `http` (`MultipartFile.fromPath`) шлёт `application/octet-stream`** —
  он НЕ определяет MIME по расширению. Backend проверяет `content_type.startswith("image/")` и
  отклоняет 400 «Нужен файл-изображение» → в UI «не получается сменить фото», молча. Решение: явно
  задавать `contentType: MediaType('image', …)` (пакет `http_parser`) по расширению файла. У Dio
  (Квартал) проблемы нет — `MultipartFile.fromFile` ставит MIME сам, поэтому там аватар работал.
- **GoRouter `refreshListenable` поверх auth-провайдера — рефрешить ТОЛЬКО по смене статуса входа.**
  Если дёргать `notifyListeners()` на каждое изменение auth-состояния (поля профиля, аватар,
  isLoading), то при «Сохранить» весь стек роутера пересобирается → экран редактирования мелькает и
  проблёскивает предыдущий экран. Гейт: `if (prev?.status != next.status) notifyListeners();`.

## Flutter / CI
- **Пустые asset-папки в `pubspec.yaml` ломают `flutter analyze` в CI** (`asset_directory_does_not_exist`):
  git не хранит пустые папки. Решение: `.gitkeep` в каждую объявленную, но пустую папку. Локально не воспроизводится (папки физически есть).
- **`pubspec.lock` коммитим** (приложения, не пакеты) — чтобы CI ставил те же версии, что локально.
- CI пинит **Flutter 3.32.1** — держать локально ту же версию, иначе analyze может расходиться.

## Dio / сеть (Квартал)
- **Dio + keep-alive поверх `adb reverse`** даёт `Connection closed before full header`, когда dev-сервер закрывает idle keep-alive.
  Смягчение: заголовок `Connection: close` на запросах лояльности + не слать дубль-запросы разом. (Но чаще причина — упавший бек, см. выше.)

## Git (рабочее дерево)
- **`git reset --hard origin/main` СНОСИТ незакоммиченные правки в отслеживаемых файлах.** Синхронизировал
  `main` через `reset --hard`, имея несохранённые правки Arc 2 → откатились правки в `.env.example`/`tests.py`/
  docs (выжили только НОВЫЕ untracked-файлы). **Впредь:** сначала закоммить/`git stash` (или ветвись без reset),
  и только на чистом дереве делай `reset --hard`. Проверяй `git status` перед reset.
- **Мердж-конфликты в `docs/WORKLOG.md`** при параллельной сессии — оба агента пишут запись сверху. Разрешать
  вручную, СОХРАНЯЯ ОБА блока (свой + чужой), не выбирая одну сторону. Код обычно мержится авто; конфликтует только WORKLOG.
- **`git pull --ff-only origin main` иногда даёт «Cannot fast-forward to multiple branches»** (конфиг рефспеков).
  Надёжнее: `git fetch origin && git checkout main && git reset --hard origin/main` — НО только на чистом дереве (см. выше).
